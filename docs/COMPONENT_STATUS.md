## Off-chain operation and integration boundaries

The keeper discovers buckets and performs maintenance once per physical LP group, rather than once per NFT. Entry settlement additionally scans bounded canonical bucket dust and creator inboxes; this does not turn ongoing rebalancing into 1,000 NFT transactions. Keeper configuration/state now identifies `shared-pools-v2`; old state requires deliberate reconciliation without deleting pending transactions. Real signing and recovery still need staged network evidence.

The read-only indexer records confirmed raw events and ownership projections, with reorg-aware storage. It is not a hosted dashboard/API, a VRF fulfillment service or proof of ownership. NFT trait/reveal events, dynamic valuation availability, royalty balances and ERC-4906 cache refresh need release-specific integration. Per-token and bounded ordinal-range notifications exist. The optional keeper watcher detects confirmed market-driven state changes, validates the NFT binding/runtime, and uses the existing budgeted pending-transaction path; it defaults to disabled and requires staged operating evidence. Migration remains a deliberate governance/operator action.

Published/indexed rewards, pending creator inboxes and funded canonical dust are settled for incumbents before entry. Unharvested venue fees and undelivered remote rewards retain collection/delivery-time collective membership; creator funds use processing-time membership. Separate royalty receipts use their activated rarity weights. Historical USD estimates are not funded liabilities or proof of entitlement.

The requested Robinhood ZZZ/native-ETH Pons-hook LP market remains unsupported by the hookless ERC20 adapter. Activation currently takes configured pool tokens; arbitrary ZZZ/USDC input routing is absent when either token is outside the chosen pair. The $100 minimum measures net deployed LP after execution, so $100 of gross input does not guarantee activation. No actual selected-chain VRF coordinator, production bridge wrapper/backing, public deployment or real transaction is established. Equivalent-asset custody hops preserve nominal asset identity; they do not permit unrelated conversion, satellite user deposits, moving the NFT, creating membership or changing rarity.
