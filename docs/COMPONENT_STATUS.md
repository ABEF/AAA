# Component implementation status

The current development candidate includes paid dormant mint/activation, shared LP custody, timelocked future-route onboarding, repeated custody migration and immutable creator-payment receivers. Current verification is recorded in [the reward-funding review](../reports/reward-funding/README.md). The [earlier implementation update](../reports/IMPLEMENTATION_UPDATE.md) and [CI repair evidence](../reports/CI_REPAIR.md) remain scoped to their own revisions. These checks do not establish full EVM coverage, selected Pons-market support, live bridge integration, an independent audit, or funded-deployment approval.

Current local targeted verification passed 45 tests: 43 security cases and two invariant-suite tests. Python inventory is 255, with 251 portable Windows cases passed and four Unix-only cases retained for Ubuntu. Slither has 160 reviewed findings and a second internal review of all 91 High/Medium findings. The full offline Solidity run passed 279 cases with zero failures and one intentional offline fork-setup skip; exact-commit CI results remain to be confirmed in the current report. The unchanged compiler profile yields Vault runtime 24,212 bytes (364-byte EIP-170 margin) and FeeController runtime 24,203 bytes (373-byte margin). Historical readiness, shared-pool and bridge reports do not validate the changed funding entrypoints.

## Off-chain components

| Component | Current implementation | Validation |
|---|---|---|
| Keeper | Dry-run default; simulations; gas/daily budget caps; isolated external signer; durable nonce/pending state; transaction/receipt identity checks; serial execution; legacy reward routes after LP departure; canonical external receiver processing during pause/remote custody; valid positional cast calldata | RPC/process and pinned CLI parsing tests run; no live signing, provider recovery rehearsal or deployment |
| Indexer | Read-only RPC; confirmed blocks; atomic SQLite cursor/log storage; bounded reorg rollback; event decoding and NFT ownership projection | Mocked RPC/reorg tests run; no production RPC backfill/load test |

The indexer stores canonical raw events and decoded fields; it is not a complete hosted dashboard/API. Migration proposal/execution/activation/acknowledgement require deliberate operator calls; the keeper does not autonomously choose a new chain.

The requested Robinhood ZZZ/native-ETH hooked pool remains unsupported by the current ERC20/ERC20 hookless adapter. Creator-payment intake is implemented separately; its policy, deployment and the native/hook LP adapter integration still require review. Repeated migration supports equivalent assets in nominal units, not unrelated asset conversion, satellite user top-ups, or moving the economic NFT off its canonical chain.

Shared-pool revision: one bucket/physical LP per venue; NFT-specific nonredeemable shares and fee checkpoints; whole-bucket v3 migration and remote-funding membership barrier. Current evidence and limitations: [reward-funding review](../reports/reward-funding/README.md). The [pooled review](../reports/pooled/README.md) records the earlier shared-custody revision; historical verification does not audit the changed external-funding entrypoints.
