# Q03 activation gas: implementation and evidence plan

Baseline main `23be8c9b01211b0732b2bcb64c227f0e05151e0a`.
Production remains undeployed and NOT APPROVED. Existing environments and four
protected dirty files are outside the change set.

Final selection: the mapping-only global-liability-bound complementary allocator is adopted; the duplicate per-book counter and prefix-envelope variants are not. See [completed review](REVIEW.md) and [current admitted build](build/current/README.md). The original research steps below retain their planning scope.

## Objective and boundaries

Reduce the cost of complete current mint2/Entry3 activation near collection
capacity. Preserve every exact whole-unit royalty entitlement, current-owner
right, cutoff/failure cohort, LP share and financial/custody guard. Retain the
reviewed20M contribution budget with full20% margin, existing1M optional sync
allowance, all defaults and normal bytecode/initcode limits.

No arbitrary set of16 gas-burning token reads is guaranteed to fit20M: their
existing isolated calls alone can consume16M. State that boundary honestly.
No healthy currency is silently skipped and no extra holder transaction is
introduced to make a measurement pass.

## Stages

1. Reuse exact historical traces to distinguish real storage work from repeated
   calls; do not rerun old tests. Record initial constraints separately from
   later alternative-representation research.
2. Prototype a complementary exact-unit tree credit in TEST-ONLY source. For a
   large remainder, allocating the upper quotient to the eligible prefix and
   subtracting one from the small excluded cyclic interval can reduce cold tags.
   Checked actual outstanding units bound modulo internal tags. Independent
   arithmetic, UINTMAX, partial claims, prefix growth and rollback must agree.
   No production promotion follows from theoretical equivalence alone.
3. Build a NEW full host: actual pinned SeaDrop issuance/fixture VRF,999 actual
   prior Entry contributions and a dormant entrant within the real600/300/100
   stock. Exercise current complete ETH/ZZZ entry, pending/opening allocations
   and a faulty currency. Suppress setup trace volume only, never economic calls.
4. Export authenticated state into new account-free, loopback-only Anvil nodes.
   Verify naturally cold complete estimates plus full20% and the exact padded
   calls. Separate successful budgets, atomic refusals and32M diagnostics.
5. Promote only a demonstrated beneficial implementation that passes normal
   runtime/initcode gates. Fresh immutable factory payload/build/consumer pins
   must be explicit; older payloads and evidence remain historical. Preserve
   flattened canonical accounting; never reinterpret a nonempty old raw book.
6. Run only NEW/affected accounting, lifecycle and consumer checks. Update the
   sole Todo, operator procedure, feature reference and memory with actual
   outcomes and limits. Publish source/docs on main; perform no rollout.

## Required companions and evidence

- Independent per-ticket raw-unit oracle; exact drains, repeat-zero claims,
  newcomer exclusion and future-only rights after token recovery.
- One-hour opening cutoff and homogeneous weight2/3 to mixed-book transitions.
- Canonical per-NFT export/import and abort preserving stored claims.
- Separate actual allocated backing from prefunds, unallocated opening/orphan
  balances and LP/buyback/compound reserves.
- Confirm source/ABI/storage delta, current factory carriers, constructor graph
  and normal limits; failing attempts stay recorded, not renamed into passes.
- Local controlled sources/market depth are not actual Robinhood market,
  provider/fee/VRF/OpenSea or operating approval.
