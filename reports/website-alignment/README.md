## Critical boundaries and remaining release gates

- The selected Robinhood native-ETH/Pons-hooked market remains unsupported by the current hookless ERC20 LP adapter. Its documented zero core LP fee is not a proportional hook-revenue entitlement. Creator-payment intake can allocate actual funds; it does not establish a payment agreement or implement the market's custody integration. Arbitrary USDC-to-pool input routing is not supplied.
- Matching a VRF-v2.5 coordinator ABI and testing a mock does not verify a proof-verifying coordinator on the selected chain. Real coordinator/lane/subscription/consumer setup, confirmations, funding, fulfillment and callback gas need review. Missing an earlier fulfillment intentionally blocks later ordered reveals; no cancellation, reroll or coordinator replacement exists.
- Production bridge provider authentication, backing, equivalent assets, finality, configuration and live multi-chain staging remain absent. Timelocked route admission is a governance power, not proof that arbitrary future code preserves principal.
- Collective rewards use receipt/processing-time membership for unharvested, unpublished or delayed remote revenue. Already indexed rewards and settled pending local inbox funds exclude new entrants; no historical fee-generation entitlement is reconstructed across delayed bridge delivery.
- LP receipts use exact 20-unit batches of 16/2/1/1. Before entry/departure, up to 19 raw units of funded dust settle to existing owner shares. This rounding exception can be material for low-decimal/high-unit-value assets and requires asset-policy review. Global index dust stays reserved and per-NFT fractions carry.
- Only reviewed exact-transfer, non-rebasing assets may be admitted. Positive rebases cannot be distinguished from donations; a broken admitted royalty token can block activation synchronization. Constructor/admission/no-eligible-member funds remain quarantined rather than becoming later windfalls.
- The 16-total-historical-bucket constraint and worst-case distinct-pool gas must be checked against final source and target-chain limits. The previous 32-bucket entry measured 16,311,524 gas and exceeded the unchanged 12M local workload budget, so the cap was reduced to 16. A 1,000-NFT workload sharing one physical pool does not prove all-pool settlement feasible.
- Current oracle-marked NAV is neither redeemable principal nor a guaranteed value/return. Production ZZZ pricing, sequencer/outage policy, wrappers/tokens, keeper economics/MEV, immutable artwork root, authorities and mint recipient need review.
- Local compilation, tests and source-bound static-analysis triage are complete for this candidate. Staged operation evidence and an independent external audit with remediation remain required. No public-chain deployment, signature or real transaction occurred in this work.
