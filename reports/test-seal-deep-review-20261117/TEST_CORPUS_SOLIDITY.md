# Solidity test-corpus context

Inventoried **148 Solidity files**, including **122 `.t.sol` files**, and **1521 declared test/invariant methods**. These are declarations, not Forge discovery or passes; inheritance can produce additional runnable copies and opt-in gates can exclude execution. No whole suite, invariant campaign or public fork was run for this inventory. The JSON records every declared method with contract, inputs, qualifiers, location and source-body digest.

The assessment distinguishes current production-source models from deliberate historical implementations, differential baselines, helper-only files and archived noncompiled `.sol.txt` material. A date, filename, missing stub selector or keyword alone does not establish obsolescence. In particular, mint-only/component fixtures do not need the LP first-reservation seam.

## Source-traced findings

- **Invariant handler first-reservation reachability:** both handlers replaced the repaired base Migration binding with deployed `activePlan`-only objects. The actual path is first activation → Vault._reserve → Budget.validateReservation → Migration.validation. The two new fixtures supply real controller-bound validation children; focused positive seed/harvest and seed/royalty-claim methods are recorded separately. No fail-open boolean stub or invariant campaign is substituted.
- **Positive artwork setup:** NativeFeeRewards, PooledRewards, RewardsAndFees and opt-in UniswapV4Fork used bare `ipfs://` with the current NFT/renderer. Those inputs were corrected to explicit nonempty TEST-ONLY roots. Intentional negative/baseline controls are preserved. Three meaningful affected accounting cases are selected separately; the public fork is not executed.
- **BuybackExecution native-versus-synthetic admission:** setup used native input=address(0) with an ERC20-only helper that rejected zero. It now uses an isolated test-only native Registry validating the real local reciprocal Manager/core/State/PosM/Permit2 graph, while retaining native/fixed-ZZZ/hookless/fee/Oracle/Rewards and lifecycle checks. Three selected burn/rollback/authority cases have separate verification; no whole-25-method or real-market claim.
- **Old optional wrapped fork:** after the URI correction, setup still lacks the synthetic helper's fixed ZZZ identity, while positive WETH/ZZZ Manager paths disagree with current Math.nativeConfig requiring native currency0/isNativePool. It needs deliberate archival/native adaptation; pinned old market facts remain historical. No external RPC was used to pretend this is qualified.
- **Delegated execution math:** custom adversarial, holder-exit, bare canonical, portfolio-accounting and scale fixtures lacked the current executionStrategy/math interface. Positive setup can fail before its intended scenario; broad expected-revert tests can also hide a wrong failure cause. These source-traced families were assigned to a parallel fixture-only adaptation with actual math, not permissive placeholder returns; its exact verification is separate.
- **Shared-base sensitivity:** the repaired PooledVaultFixture, execution adapter and fixed-ZZZ getter propagate to descendants. Inherited baseline reuse retains exact source stages; an automatically generated inventory never converts unchanged historical evidence into current runtime acceptance.
