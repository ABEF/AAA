## Established choices retained

- **Keeper waiting is service-only by explicit decision.** Only authorized keys
  can submit keeper calls. Alternate software with an authorized key can ignore
  extra service rules where contracts permit; revocation/rotation, pause and
  on-chain financial/custody checks are the existing recovery boundary.
- **Financial emergency masks are explicit governance authority.** They may
  waive selected price/timing/value checks, not exact authority, fixed token/core
  identities, callbacks/backing or terminal state. Force is never selected by an
  automatic fallback.
- **Loss caps are per operation.** The user declined a cumulative limit; no
  cumulative restriction or guarantee is inferred.
- **Ordinary contributions only place entrant funds.** If releasing incumbent
  compound makes idle exceed5%, entry atomically rejects. Eligible keeper
  compound/rebalance or separately reviewed manual recovery restores usable
  placement; a new contribution does not secretly deploy incumbent principal.
- **Raw residual close, mode disable and consolidation differ.** Closing only the
  residual retains attributed idle and desired mode; same-main consolidation
  already reinvests and disables future residual mode atomically; full emergency
  replacement does not itself disable desired mode. There is no second hidden
  add-LP step after successful consolidation.
- **Valid capacity and sale commitments remain permanent.** Four registered
  buckets remain bounded; an expired configured sale end cannot be reopened
  merely because bootstrap has not minted or sealed. These are not new bugs.
- **Royalty recovery uses active weights at inclusion.** The review hash is not
  a beneficiary freeze. Already earned entitlements remain separate. The
  optional deposit-stop workflow is the existing tool for a stable recovery
  cohort; global pause would block allocation.
- **Terminal principal is paid as an atomic ETH+ZZZ pair per NFT.** External
  token/receiver failures retain backing but may defer that pair. Original-
  currency royalty and healthy reward entries can be handled separately. A
  split principal-liability redesign would need an explicit reviewed decision.
