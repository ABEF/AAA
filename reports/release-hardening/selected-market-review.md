# Selected native-ETH/Pons market: internal feasibility review

Reviewed 2026-10-15. **Design review, not implementation, an independent audit or funded-use approval.** No pool guards, contracts, provider settings or authorities were changed. All public-chain operations were reads; no transaction was signed, broadcast or deployed.

The selected market is technically approachable through a typed native settlement adapter that normalizes ETH to a reviewed WETH for PoPL accounting. It is **not compatible with the current candidate**, and replacing a zero address with WETH or simply permitting hooks would not implement it safely. The actual Uniswap pool identity and the accounting assets must be represented separately and consistently.

## Required adapter and accounting design

1. **Keep the real PoolKey.** PoPL currently derives idle assets, oracle reads, reward currencies, home provenance and migration compatibility from `PoolConfig.key.currency0/1`. The adapter also checks the LP NFT's actual key against its pool ID. An invented WETH/ZZZ key names a different pool. Introduce explicit, reviewed venue-currency-to-accounting-asset mapping, preserving the real native/Pons key and nonzero canonical WETH/ZZZ accounting assets. Migrate every affected consumer together: Vault, Strategy, Fees, metadata valuation, Buyback, migration registry/import and off-chain validation. Do not overload a zero address already used for absent bridge assets or add unrestricted calls. See `ZZZVault.sol:98-135,176,217-224,447-448`, `ZZZLiquidityManager.sol:47-57`, `ZZZStrategy.sol:21,78-90`, `ZZZNFTMetadata.sol:43-46`, `ZZZFeeController.sol:130-133` and `ZZZMigrationRegistry.sol:35-46`.
2. **Normalize only at a constrained boundary.** Pin the exact wrapper, runtime and 18-decimal, exact 1:1 deposit/withdraw behavior. Preserve real venue slot orientation even if the wrapper address sorts differently from its paired ERC20. Pull WETH/ZZZ into the adapter, unwrap only the operation's authorized WETH budget, pay native debt and wrap native credits/remainders before returning assets to the Vault. Native ETH must not become a general Vault/rewards/bridge ledger asset. Keep LP NFT ownership in the Vault, only per-position approvals, and exact spent/received checks. Existing creator-payment wrapping is a separate funded-intake helper, not this LP integration.
3. **Settle actual deltas, not assumptions.** Pinned v4 `DeltaResolver._settle` uses `sync(currency)` followed by `settle{value: amount}` for native currency. The reset is needed even for native debt because the synced currency is transient shared state. ERC20 settlement still requires exact transfers and cleared Permit2/ERC20 approvals. For PosM mint/increase, pass the bounded native value to its payable `modifyLiquidities`, then explicitly recover only the expected remainder; taking native credits to the current Vault directly is incompatible. Use reviewed typed actions and fixed recipients. Raw `SWEEP` of all PosM/adapter balances must not credit an operation with another party's prefunds/donations. Protect balance snapshots, authorized native senders, expected callbacks, operation identity and all reentrant paths. Forced ETH is not user contribution or earned revenue. See pinned `DeltaResolver.sol:37-47`, `NativeWrapper.sol:33-35`, `PositionManager.sol:172-178,245-279,442-451` and `PoolManager.sol:349-366`.
4. **Admit only the reviewed hook behavior.** Pin code, actual pool, factory/core bindings, permission bits and allowed per-pool fee terms. The retained hook enables initialization and swap callbacks, not liquidity callbacks; arbitrary hooks with liquidity return deltas must remain excluded. Its `_afterSwap` takes an unspecified-currency fee and returns the corresponding delta. A swap's usable output must be measured after that adjustment, including hook fee and price impact inside reviewed all-in slippage limits. Existing exact-input checks must still reject partial input, insufficient output and spoofed callbacks. Do not assume fee 0 means cost-free balancing. Hook implementation and third-party authorities need independent review, not just an address-mask check. [Uniswap hooks](https://developers.uniswap.org/docs/protocols/v4/concepts/hooks).
5. **Preserve accounting and nonredeemability.** Snapshot exact canonical ERC20 balances across native conversion, maintain attributed idle versus principal/reward reserves, and settle incumbent indexes/inboxes/dust before share issuance as today. Mint ETH proceeds remain isolated. Activation still requires $100 of **net actually deployed** LP: $100 worth of input may be insufficient after conversion fees/price impact. Do not lower that check to make the preview's round input succeed. No new principal refund, rescue or claim route is introduced by wrapping.

This is a cross-module design change, not a safe one-line guard exception. Vault runtime already has little margin; remeasure normal deployment/initcode and worst-case operation gas before selecting an implementation. The existing hookless adapter and production validator must continue rejecting this market until the full integration and independent review are complete.

## Revenue, ZZZ/USDC entry and migration

The [Pons integration documentation](https://docs.ponsfamily.com/v2#uniswap-v4-pools) describes zero core fees and hook revenue distributed to configured recipients, rather than ordinary LP fee growth. Ordinary additional PoPL liquidity is therefore not an automatic hook-revenue entitlement. Existing creator-payment intake can account actual transfers under 80/10/5/5; no creator percentage, timetable or continued payment is established. Retained source freezes fee-rate terms at registration while creator recipient/buyback enablement have separate factory-controlled changes. Re-read and review those authorities. Pons's [audit disclosure](https://docs.ponsfamily.com/v2#audits) currently lists reviews in progress; completed independent upstream review is not established here.

ZZZ can be balanced into the pool's two currencies by a compatible adapter; concentrated-liquidity amounts follow price/range, not a universal 50/50 split. **USDC is not a currency of this pool.** A separately reviewed fixed/allowlisted conversion path, real USDC address/decimals, sufficient route liquidity, bounded min output, deadlines and exact approvals are required. Existing `_requireOwner` and pair-token pulls mean an external zapper cannot simply call `activate` for another wallet. Either perform an owner-controlled swap followed by normal activation, or separately design an atomic typed owner-authorized contribution entrypoint with replay protection and immutable NFT/bucket/recipient intent. Never transfer the NFT to a zapper or grant it claim/principal privileges. Refund only uncommitted current-operation input; admitted LP/idle remains attached. See `ZZZVault.sol:84-86,160-163,223-224` and `ZZZStrategy.sol:63-90`.

Canonical WETH/ZZZ can preserve existing exact-ERC20 bridge vectors: close the native venue position, wrap, then deliver exact reviewed equivalent tokens. Reopening a native venue at a future destination needs that destination's reviewed wrapper mapping and venue integration. Native addresses must not enter `BridgeAssets` principal vectors, and wrapper/decimals/backing cannot be assumed equivalent across chains. Returning custody must restore the same canonical identity and liabilities. No SDK wrapper, backed ZZZ route or post-provider-custody recovery has been implemented; no bridge or arbitrary conversion is approved by this proposal. See `BridgeAssets.sol:14-18`, `ZZZMigrationReceiver.sol:40-55` and [bridge onboarding](../../docs/BRIDGE_ONBOARDING.md).

- Keep negative tests for native/unapproved hooks, wrong actual-key/accounting mappings, permission-mask/code changes, malicious wrappers, stale feeds, spoofed callbacks, dirty synced currency, forced ETH, prefunds and failed remainder handling. Prove atomic rollback and no residual approval/debt.
- Add **actual selected-pool** pinned-block fork tests for permissionless mint/increase/collect/close, both exact-input swap directions, net hook fee, native remainders, one shared position and range rebalance. Retain the existing hookless tests separately. Do not label mock or alternative-pool coverage as selected-market qualification.
- Extend independent ledger/invariant tests across entry/top-up/transfer, creator funding during every conversion callback, compounding/buyback, pause, native wrapper failures and all reward fractions. Preserve all holder shares, fee liabilities, royalty weights and principal attribution through native operations.
- Test canonical-to-satellite-to-satellite-to-home/revisit with exact wrapped assets and real provider backing/finality, ACK ordering, delayed rewards and failures. Initial migration-disabled scope may remain explicit until that work is approved.
