## First challenge

- Retired bridge/custodian/creator-income/Power/multi-input assumptions would
  resurrect removed architecture. Current ETH/fixed-ZZZ, native custody and
  terminal holder return govern this campaign.
- Earlier494-body and122-output gaps were already resolved; reuse exact source
  evidence instead of announcing them again as new work or rerunning unchanged
  suites. Inspect current composed consumers before admitting reuse.
- A generic security checklist misses normal-operation liveness, service budget,
  restoration, controller trust and actual1,000-NFT shared accounting.
- Public read/unsigned, demo, historical Anvil and current4 source are different
  environments. Wallet/deployment/service authority is not implied by an audit.

## Second challenge

- Treat concurrent/reordered operations, stale clocks, partial data and operator
  mistakes as complete state transitions; isolated function checks are not enough.
- Include evidence-producer admission, source capture before imports, compiler
  advisory applicability, lifetime replay growth and actual operating funding.
- Preserve relevant checklist domains while excluding nonexistent AI, password
  accounts, protocol consensus, bridges and mandatory committees. Domain-specific
  controls still apply to dependencies, RPC, content and key management.
- Require useful reproduced corrections, exact source/result pins, explicit
  platform/tool/fixture limits and one status ledger. No blanket safety guarantee,
  automatically widened financial limit or invented provider qualification.
